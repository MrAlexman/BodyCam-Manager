# Конфигуратор сборок Bodycam

Локальное настольное приложение для игрового снимка Bodycam 0.9.1. Выберите модель, замените детали, закрепите нужные слоты и подберите сборку под одну цель или несколько целей с весами. Редактор, подбор и сравнение используют один расчёт.

## Запуск

Поместите `main.py` и `bodycam_catalog.json` в одну папку. Для Windows 10/11 нужен Python 3.11 или новее с компонентом Tcl/Tk. В PowerShell, открытом в этой папке, выполните нужную команду.

| Команда | Результат |
| --- | --- |
| `python main.py` | Окно с вкладками «Конструктор», «Подбор», «Сравнение» и «Пресеты». При первом успешном открытии SQLite получает архив исходного каталога. |
| `python main.py --validate` | Проверка внешнего справочника, версия, количества и SHA-256. При ошибке выводится путь к полю. |
| `python main.py --self-test` | Автономные примеры на встроенных данных и временной БД. Рядом с исходным каталогом дополнительно запускаются проверки игровых примеров. |
| `python main.py --import-xlsx "Bodycam_Loadout_0.9.1.xlsx"` | Новая папка рядом со скриптом с отдельным кандидатом, поадресной сверкой и перечнем отличий. Путь книги можно указать абсолютный. |

Обычная работа, валидация и самопроверка используют стандартную библиотеку. Если нужен импорт, установите зависимость командой `python -m pip install openpyxl`. Код завершения служебной команды равен 0 при успехе и ненулевому значению при ошибке. Папка программы должна быть доступна для записи при импорте кандидата. GUI сохраняет пресеты в пользовательском профиле.

## От ручной сборки до сохранённого результата

1. В «Конструкторе» выберите модель, затем слот в левом списке. В центре доступны варианты замены и строка поиска по имени. Кнопка «Карточка…» показывает источник детали, допуски, точки, операции и ревизию. Примените выбранную деталь и закрепите слот, если подбор должен сохранить этот выбор.
2. У каждого слота три возможных действия. «Штатно» применяет заводскую деталь этой ревизии, «Снять» оставляет пустой слот, явный выбор сохраняет конкретный ID. Подтверждённая установка открывает показатели. Красный или жёлтый статус сохраняет выбранные ID в черновике и показывает причину. Переключатель над деталями открывает остальные варианты.
3. В «Условиях расчёта» задайте здоровье условной игровой цели, попадания и нужные параметры цикла или питания. Для особого цикла введите переходы в секундах через пробел, например `0,1 0,5`. Знак `?` сохраняет неизвестный переход. В поле питания можно выбрать сценарий без магазинной модели. Расчёт использует постоянный урон. Параметры сценария сохраняются вместе со сборкой. Выбор показателя с неизвестной базой позволяет прочитать основание, а при доступном отношении множителей — посмотреть изменение к штатной.
4. В «Подборе» выберите режим, добавьте цели, при необходимости задайте порог и размер выдачи K (1–20, по умолчанию 5). Для взвешенной цели укажите вес и диапазон. Подбор может продолжаться в фоне. «Лучшие из проверенных» означает предварительную выдачу. После отмены остаются проверенные составы, счётчик и условия запроса.
5. Добавьте свою сборку и две найденные в «Сравнение». Выберите опору или включите «Только различия». Столбцы хранят независимые снимки. При добавлении пятого выберите, какой заменить. Пересчёт под действующую ревизию создаёт новый снимок.
6. Сохраните строку подбора в «Пресеты». После перезапуска откройте запись, чтобы вернуть состав, фиксации, шкалы, веса, пороги и статус доказанности. Для ручной сборки можно сохранить только состав с условиями. Имена можно изменять, записи копировать и удалять с подтверждением.

## Расчёт, основания сравнения и рейтинг

Десятичные входы преобразуются в рациональные числа. Ядро применяет `B × произведение(mul) + сумма(add)`. Одинаковые `set` задают итог. Для разных `set` нужны явные приоритеты, а значения на старшем приоритете должны совпасть. Штатное наблюдение S используется для заводского состава. Из него можно восстановить базу как `(S − Aшт) / Mшт`, если заводской набор обходится без `set` и Mшт отличен от нуля.

Профиль «По опубликованным эффектам» принимает отсутствующую операцию за нейтральную. У положительного индекса с неизвестной базой отношение чистых множителей позволяет получить процент к штатной. Спорный эффект помечает затронутую величину и зависящие от неё результаты. Время, индекс скорости и относительный процент хранятся отдельно. `unknown`, `not_applicable`, `unreachable` и известный нуль различаются. При округлении на экране точная середина округляется к чётному.

В одиночном режиме сравниваются точные значения выбранного показателя в указанном направлении. Во взвешенном режиме для максимума используется `u=(x−L)/(U−L)`, для минимума — `u=(U−x)/(U−L)`. Итог равен сумме `100 × w × u / Σw`. Диапазоны общие для всех кандидатов запроса. Выход за диапазон отмечается, балл продолжается линейно. Нулевой вес отключает вклад, самостоятельный порог остаётся. Неизвестная обязательная величина исключает кандидата.

При равных точных значениях выше стоит сборка с меньшим числом замен относительно штатной. Далее сравниваются ID эффективных деталей в порядке слотов, пустое значение идёт первым. Ручные действия `stock` и явный выбор одной и той же штатной детали сохраняются как разные намерения, их состав представлен в рейтинге один раз. Полный перебор подтверждает топ. Для больших пространств с поддерживаемыми базовыми целями поиск также может подтвердить результат по оценке наилучшего возможного балла с проверкой ничьих. Для производных целей и сложных сочетаний время зависит от пространства поиска. Фиксация слотов ограничивает его по запросу игрока.

Сравнение показывает разность известных абсолютных значений и относительное изменение при ненулевой опоре. Для процентов от общей штатной базы оно использует процентные пункты. В сравнении разных моделей такой процент справочный. Изменение здоровья цели влияет на сопоставимость времени её достижения, ёмкость остаётся сопоставимой. Все равные лидеры отмечены словом «лидер» и цветом.

## Обновление, редактирование и восстановление

- Перед правкой сделайте копию JSON. Сохраните кодировку UTF-8 и отступ в два пробела. Увеличьте положительное целое `revision` для изменения внутри патча. Для нового игрового снимка задайте `game_version`, дату и источники. Схема и расчёт поставки имеют версию 1.
- Создавайте источники в `sources`. У факта укажите `source_id` и адрес `locator`. Для числового `known` нужно конечное число. У `unknown` и `disputed` значение равно `null`. У спорной записи сохраните исходный текст либо число и причину. В `unresolved_effects` перечислите `affected_stats` или используйте `["*"]` для неопределённой области.
- Для модели заполните `class`, `name`, `values`, `slots` и сведения о точках. У экземпляров слотов задаются `type`, `order`, `required`, `stock_module_id`. Для новой детали укажите `slot_type`, `effects`, источник и стабильный ID. Определите допуск для каждой известной пары в `compatibility`. Установочный запрет требует документированного основания. Отсутствующая пара даёт «нет сведений».
- В `requirements` внешние группы обязательны, элементы внутри группы — альтернативы. `provides` описывает точки этого узла с локальным ID, типом и ёмкостью. Требование может ограничивать поставщика. Два потребителя конкурируют за конечную ёмкость, виртуальное условие проверяет наличие. `excludes` действует в обе стороны. Для неполных сведений заполните `points_complete=false`.
- Для метрики задайте единицу, направление, точность и смысл. Для производной выберите поддерживаемый `formula_id` и перечислите зависимости. Поддерживаемые формулы версии 1 находятся в разделе `stats` поставляемого файла. Новая формула с новой семантикой требует изменения расчётного кода.
- Для обновления из XLSX сначала создайте кандидат и изучите `cells.csv` и `changes.jsonl`. После проверки перенесите принятый кандидат на место `bodycam_catalog.json`, запустите `--validate` и нажмите «Перечитать справочник». Изменённое содержимое под уже архивированной парой версия/ревизия отклоняется. Идентичность определяется SHA-256 канонического JSON, включая порядок массивов.
- В Windows архив и пресеты находятся в `%LOCALAPPDATA%\BodycamConfigurator\presets.sqlite3`. На Linux используются `$XDG_DATA_HOME/BodycamConfigurator` или `~/.local/share/BodycamConfigurator`. Для резервной копии закройте приложение и скопируйте БД. Архив создаётся при первой активации, до первого пресета.
- При повреждении внешнего JSON программа открывает последнюю рабочую ревизию. Если архив пуст, можно исправить файл и перечитать его из открытого окна. При недоступности постоянной БД приложение объясняет переход на хранение в памяти до закрытия.
- Открытие пресета обращается к его архивной ревизии. Перенос на текущую ревизию создаёт копию с исходными именами, списком утрат, конфликтов и изменившихся чисел. При конкурирующей записи редактор предлагает перечитать пресет или сохранить копию. Для потерянной архивной ревизии доступен сохранённый читаемый снимок.

Сведения из строк пользовательского выбора на листах классов в состав каталога не попадают.

### Пример и расхождения

Данные!A17 определяет модель SG5-K (`sg5_k`), G17 задаёт штатное цевьё m91. Справочник!A99:C99 определяет альтернативу m94 Tropic, X99 разрешает её на этой модели, J99 не указывает точку underbarrel. Для m176 Shifter ячейка I181 требует такую точку, а ПП!AH14 ограничивает поставщика цевьём. После установки Tropic и Shifter игровой редактор показывает конфликт и хранит оба ID. Если снять Shifter и выбрать также Hartos (m116) и Curved 15 (m428), скорость ADS относительно штатной меняется на +50%, ёмкость равна 15. Абсолютное время ADS неизвестно.

121 спорная операция и 2 записи с неподтверждёнными эффектами доступны через `modules[id].unresolved_effects`. Три строки с подписью Fire Rate расходятся по смыслу с интервальным каналом книги, в том числе G103/CR103. В 97 строках скорость перезарядки расходится с колонкой длительности, в том числе G433/AY433. Ещё 21 раз текст задаёт фиксированное Magnified Kick Hip, а числовой set в CK пуст, например G226/CK226. Их неопределённость привязана к соответствующей метрике. В строках G200 и G208 явно не подтверждены эффекты всего модуля для патча, поэтому область равна [«*»].

### Чтение поадресной сверки

`--import-xlsx` печатает путь отдельного каталога с `bodycam_catalog.candidate.json`, `cells.csv` и `changes.jsonl`. CSV в UTF-8 с BOM содержит 60 007 адресов, включая 226 заголовков, служебную строку и пустые значения. В `locator` находится адрес, в `raw` исходное значение JSON, в `destination` — путь JSON Pointer. `state`, `reason`, `affected_stats` описывают преобразование, исключение или неопределённость. Исключённые ячейки и заголовки имеют пустой путь. `candidate` и `active` показывают значения по пути назначения, `different=yes` отмечает отличие. Полные изменения структуры, включая ручные поля вне импорта, записаны в changes.jsonl.
